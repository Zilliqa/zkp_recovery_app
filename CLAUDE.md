# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Zilliqa "ZKP recovery / migration" app. A user with a legacy Zilliqa (Schnorr, SHA-256-derived) address proves, with a Groth16 zero-knowledge proof, that they know the mnemonic seed controlling that address. The proof binds the old address to a new EVM destination and a chain-id `domain`, and the seed is never revealed. The output is calldata for the escrow's `claim(uint256[2],uint256[2][2],uint256[2],uint256[4])` (selector `0xcf1c9461`, 388 bytes). The user submits it through a Google Form, and `claim-relayer` submits it on-chain.

The root `README.md` is the stock mopro template. The project-specific docs are in `groth16-prover-min/README.md`, `claim-relayer/README.md` and `docs/{Linux,Windows}.md`.

## Repository layout (how the pieces connect)

- **Root Rust crate `zkp_recovery_app`** (`src/`, `build.rs`, `Config.toml`): a mopro-ffi crate that wraps `circom-prover` (Arkworks). `build.rs` transpiles `test-vectors/circom/groth.wasm` into Rust with `rust_witness`. `src/lib.rs` registers the circuit under the key **`"groth_final.zkey"`**, and `generate_circom_proof` looks up the witness function by the zkey path's *file name*. That means the zkey on disk must be named `groth_final.zkey`, and the Flutter download service saves it under that name. `Config.toml` targets only the `circom` adapter and the `flutter` platform. The `// HALO2_TEMPLATE`, `# CIRCOM_DEPENDENCIES` and similar markers are mopro CLI anchors; leave them in place.
- **`mopro_flutter_bindings/`**: a Flutter plugin generated by `mopro build`. It uses flutter_rust_bridge 2.11.1 and cargokit. `rust/Cargo.toml` depends on the root crate via `path = "../.."` with `features = ["flutter"]`. The Dart bindings in `lib/src/rust/` (including `third_party/zkp_recovery_app.dart`) are generated, so don't hand-edit them. Run `mopro build` again after changing the Rust API or the circuit.
- **`flutter/`**: the desktop/mobile GUI (package `zkp_recovery_app`, shipped as `zkp_migration_app`). Its release targets are macOS, Linux and Windows through WSL2.
  - `lib/services/proof_service.dart` holds the core logic. It turns a BIP-39 mnemonic (plus an optional passphrase and language, with Japanese using ideographic spaces) into a BIP-32 master key. It then scans derivation paths to find the parent node of the old address:
    - Ledger: `m/44'/313'/n'/0'/0'` with n<1000, giving `isHardened=1`.
    - Other wallets: `m/44'/313'/n'/0/i` with n<10 and i<100, giving `isHardened=0`.
    It builds the circuit inputs (`parentPriv` and `parentCC` as 256-bit arrays, `addrIndex`, `isHardened`, `expectedAddr`, `newAddr`, `domain`), proves, verifies locally, and ABI-encodes the claim calldata. Note that the G2 `b` coordinates are swapped (`[1]`, `[0]`) for Solidity.
  - `domain` is hard-coded per build: **`32769`** for release (zq2 mainnet) and **`33101`** for `kDebugMode` (zq2 testnet). The escrow checks `pubSignals[2] == block.chainid`. `dev-chain.patch` is a local, uncommitted override to `33469` (devnet); don't commit that change.
  - `lib/services/download_service.dart` and `lib/models/download_status.dart` download the ~358 MB proving key from GCS into the app-support dir, caching it with ETag metadata. They also check its SHA-256, which is pinned in `ProvingArtifacts`. The key is checked again right before every proof.
  - The UI is a stepper: `widgets/onboarding_stepper_page.dart` hosts the `*_step_content.dart` steps.
- **`groth16-prover-min/`**: the reference Node/snarkjs prover and the **source of truth for the circuit** (`circuit.circom` and `bip32lib.circom`, circom 2.2.3, pinned includes). Only the final BIP-32 CKD step runs in-circuit, which comes to about 679k constraints. Public inputs are `[expectedAddr, newAddr, domain, isHardened]`. `build-circuit.sh` rebuilds reproducibly, applies `patches/circom-ecdsa-dummy-point.patch`, and checks that the output is byte-identical. The production zkey comes from the ceremony: sha256 `87191dc2…`, recorded in `groth16-cli-ceremony/TRANSCRIPT.md`. A zkey from a local `snarkjs zkey contribute` is a DEV key and must never be deployed.
- **`plonk-prover-min/`, `plonk-setup-min/`**: PLONK variants of the same circuit, kept only for the case where no ceremony is wanted. They are not used by the app, and their key is 3.7 GB with about 20 min proving.
- **`groth16-cli-ceremony/`**: phase-2 trusted-setup tooling, with `contributor/` and `operator/`.
- **`claim-relayer/`**: Node ≥22 ESM (ethers v6, built-in `node:sqlite`). It reads new Form rows from a public Google Sheet through gviz JSON, using a timestamp watermark and keying rows by `hash(timestamp+calldata)`. For each row it shape-checks the calldata, simulates `claim()` with `eth_call`, and only then submits. It keeps per-row state in SQLite and uses a PID lock so only one instance runs. The relayer key only pays gas, because the destination is bound inside the proof.

## Common commands

Rust / bindings (from the repo root; requires `cargo install mopro-cli`):
```sh
# Prereq: the production zkey at test-vectors/circom/groth_final.zkey (not in git)
curl -L -o test-vectors/circom/groth_final.zkey https://storage.googleapis.com/bkt-p-zkproof-files-001/groth16/final.zkey
mopro build                      # build Rust lib + regenerate mopro_flutter_bindings (release mode, flutter platform)
cargo test -- circom_tests       # Groth16 prove+verify self-test in src/lib.rs (needs the zkey)
cargo test                       # also runs uniffi foreign-language tests; README says to put jna-5.13.0.jar on CLASSPATH
```
If the circuit changes, copy the new `circuit.wasm` to `test-vectors/circom/groth.wasm` and run `mopro build` again.

Flutter app (from `flutter/`):
```sh
flutter pub get
flutter analyze
flutter test                                   # unit/widget tests (test/circom_test.dart, test/widget_test.dart)
flutter test test/circom_test.dart             # single file
flutter test --plain-name "throws when evmAddress equals zilAddress"   # single test by name
flutter test integration_test/plugin_integration_test.dart   # needs a device/simulator
flutter run -d macos                            # or linux
flutter build macos | flutter build linux
```

Reference prover (from `groth16-prover-min/`, needs `circuit_final.zkey` downloaded there, ~8 GB RAM):
```sh
./run-proof-secure.sh <oldAddr 0x..|zil1..> <newAddr> <domain>   # mnemonic via hidden prompt
node secure_core_test.js                                          # dual-mode binding self-test
./build-circuit.sh                                                # reproducible compile + byte-identical check
```

Claim relayer (from `claim-relayer/`):
```sh
npm install && cp .env.example .env
node relay.js --dry-run     # read-only: ingest + simulate, no DB writes, no lock
node relay.js
cd e2e-forge && forge test  # escrow + verifier logic, in-process
e2e-anvil/run.sh            # full relay.js path against anvil --chain-id 32769 (see e2e-anvil/README.md)
```

## Things to keep consistent

- The four public inputs, and their order `[old, new, domain, isHardened]`, are shared by the circuit, `vk.json`/`verifier.sol`, `ProofService.encodeCallData`, the relayer's 388-byte length check, and the escrow. If you change one, update all of them.
- The prover code checks both address inputs are exactly 20 bytes and non-zero, and that `old != new`. The circuit range-checks both as 160-bit values.
- Branching follows git-flow: `develop` for integration, `feature/*`, `release/vX.Y.Z` merged into `master` and tagged. The app version lives in both `Cargo.toml` and `flutter/pubspec.yaml`, and the root `Cargo.toml` version must match the `version` in `mopro_flutter_bindings/rust/Cargo.toml`'s dependency on it.

## Milestone Workflow

This project uses the milestone-driven workflow. Each milestone lives at
`milestones/milestone_<N>_<slug>/` with `requirements.md`, `open_questions.xml`,
`TASKS_TODO.md`, and `TASKS_DONE.md`. `milestones/README.md` is the source of truth for
which milestone is current. Never advance the pointer without first running
`/finish-current-milestone`.
